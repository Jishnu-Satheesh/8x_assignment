- Targeted tests for request validation, provider serialization, failed/no-image output, duplicate/concurrent requests and durable hard cap; Chrome tests for the user journey.
- `docs/PHASE2_QA.md`, screenshots and safe model verification evidence; README/env example for local setup and limitations.

## Dependencies and decisions

Use pinned `ai@7.0.150` and `@ai-sdk/google@4.0.104` directly with Google, plus `server-only`. Installed provider source must confirm aspect ratio, image size, reference and image-output support. Use the official Google SDK only if a required capability is unsupported. No new service or database.

Default Nano Banana 2 (`gemini-3.1-flash-image`); alternative Nano Banana Pro (`gemini-3-pro-image`). No preview aliases or video models. Verify the smallest practical output once per model before enabling; no high-resolution canaries. UI exposes only validated supported choices, one output per request. Future models are disabled with a Coming soon tooltip.

For this phase, history lives in the current browser session and generated bytes are delivered directly, not published into a shared library. Use server-side durable reservation with an absolute attempt cap and request throttling. Failed/uncertain dispatched attempts still consume allowance. Hosted/serverless generation stays disabled unless a suitable durable single-host ledger is explicitly configured; a filesystem counter is not represented as a distributed limiter.
